YOUR FIRST THREE VALUES

Keep the first pass small.

The initial angle mapping uses the ideal assumption elevation = 90° − hood command. Transfer 1 means no surface-speed loss. These are deliberately visible assumptions, not values inferred from the old shot table.

Verify the two geometry estimates once.

ShotModel/Setup/Release Height M starts at 0.445 m from the existing simulator/model. Measure floor to the ball's center at release and enter the measured height.

ShotModel/Setup/Wheel Radius M starts at 0.0508 m (2 inches) from the existing effective-radius constant. Verify the wheel contact radius. Use radius, not diameter; keep that choice fixed while tuning transfer.

The hub height (1.83 m), ball radius (0.075 m), mass (~0.203 kg) and air density (1.2041 kg/m³) use the project's existing field/simulation values. They are reference approximations. The advanced drag/lift coefficients are effective values relative to these references. Turret offsets and mechanism limits are read directly from Constants.

Measure the launch-angle mapping.

  1. Use your normal turret startup procedure. Turn Tune/Use Tune Values on to use the existing manual hood / wheel controls.
  2. Set Tune/Hood Deg to 13. Use a modest wheel speed that produces a clean ball exit. Record a side-on high-frame-rate video; measure the ball's initial direction above horizontal. Enter it in ShotModel/Tune/Elevation At Hood Min Deg.
  3. Repeat at hood command 29.85. Enter that physical elevation in ShotModel/Tune/Elevation At Hood Max Deg.

Use actual camera capture frame rate, not slow-motion playback speed. For better accuracy, fit the first few ball-center positions to x = x₀ + vₓt and z = z₀ + v𝓏t − ½gt²; launch elevation is atan2(v𝓏, vₓ). The hood has no position feedback, so its command is not an angle measurement.

This first model assumes the angle mapping is approximately linear. Check the middle hood setting too. If it differs materially from the line through the endpoints, record that measurement before trying to hide the error with air-drag tuning.

Find the wheel-to-ball transfer.

  1. With the robot stationary, record several releases at a fixed hood command and at least two steady wheel speeds.
  2. Read Tune/Left Turret Measured RPS or the right-side equivalent at release. Measure the ball's initial speed from the video.
  3. Compute the ratio below, average repeated trials, and enter it in ShotModel/Tune/Ball Speed Transfer.
wheel surface speed = 2 × π × wheel radius × measured wheel RPS
Ball Speed Transfer = measured ball exit speed / wheel surface speed

If you cannot measure speed yet: use a repeatable short-distance shot and adjust this one value. Consistently short → decrease Transfer to command more RPS. Consistently long → increase Transfer. Make small changes and repeat several shots.

There is no separate “compression number” and “slip number”: the same exit-speed loss can be explained by either. Exit-speed measurements identify their combined transfer, not each cause independently. Fix a wheel that is failing to reach its commanded RPS before tuning aerodynamic coefficients.

Use the model and test three distances.

  1. Turn Tune/Use Tune Values off. Hub targeting uses the precomputed radial quadratic map.
  2. Check ShotModel/Settings Valid and ShotModel/Left/Model Valid / right. Read the status text if a shot is invalid.
  3. Repeat stationary shots at a near, middle and far location in the alliance zone. Use the dashboard's actual turret-to-hub distances. Test each turret and record commanded RPS, measured RPS, hood, makes/misses and observed flight time.
  4. Keep the three main settings fixed while checking distance. A uniform speed error points back to transfer. A growing range error can justify testing drag, after verifying angle mapping and geometry.
  5. Click ShotModel/Save Settings after a useful improvement. It resets itself after saving to WPILib Preferences. Map inputs must match the exported model. After changing height, radius, endpoint angles, transfer, drag or spin/lift parameters, regenerate the map on the laptop and update the model file through your normal deployment procedure. Delay and per-side trims stay live.

The solver evaluates a validated quadratic patch for distance and radial velocity, then subtracts tangential velocity from the 3D launch vector. Uncovered regions, incompatible inputs and mechanism-limit failures produce an explicit invalid status. Coverage gaps must be resolved through calibration and fitting. The indexer/feed controls and ferry solver are unchanged.

LEAVE THESE ALONE UNTIL THE BASELINE IS CLOSE

Optional corrections, one at a time.

Distance-dependent error → dragShotModel/Advanced/Drag Cd = 0

Zero disables drag. After measuring angle and transfer, compare short and long stationary shots and their flight times. Try a small positive coefficient (for example 0.05), repeat the same shots, and change only this coefficient. Larger drag generally commands more speed for stationary shots.

Use measured flight shape and timing to separate drag error from angle/transfer error. The old FuelSim uses 0.47 as a generic sphere estimate; it is not a measured Chuck coefficient. Keep it at zero if adding it does not improve the measurements.

Visible backspin / unexpected arc → spin and Magnus liftShotModel/Advanced/Ball Spin Per Wheel Rev = 0ShotModel/Advanced/Magnus Coefficient = 0

Put a visible mark on a ball and record high-speed video. Measure ball revolutions per second near release, then divide by measured wheel RPS. Enter that ratio. Positive means backspin; negative means topspin. This ratio alone has no aerodynamic effect while Magnus Coefficient is zero.

Hold measured spin fixed and adjust Magnus Coefficient in small increments, comparing the observed arc and flight time at multiple distances. Lift and spin cannot be determined separately from range alone. Backspin adds upward acceleration initially and also changes horizontal acceleration; the required RPS does not have to decrease at every fixed elevation.

Measured spin loss during flight → spin decayShotModel/Advanced/Spin Decay Per Sec = 0

Leave zero unless you can measure spin at two times in flight. Using spin magnitudes, calculate:

decay = ln(spin at t₁ / spin at t₂) / (t₂ − t₁)

Use seconds and revolutions/second. Spin decay only matters when measured spin and Magnus lift are enabled. Do not guess this value from one missed shot.

Stationary shots work; moving shots lag → release delayShotModel/Advanced/Release Delay Sec = 0

The model already includes robot translation, rotation-induced velocity at each turret, and calculated flight time. This additional setting represents how far ahead the release state should be predicted.

Start with slow, constant motion, test both directions, then test up to 2.5 m/s and rotation. Compare the predicted flight time with measured flight time first. If aim-state-to-release delay is measurable, enter that delay in seconds. Otherwise adjust in small increments (e.g. 0.01 s), checking both directions after each change. Do not enter total ball flight time here or compensate for a wrong flight model by inventing delay.

Precompute once; evaluate while driving.

Default hub targeting now uses PrecomputedShotMap. The laptop checks all sampled angle/speed pairs, retains scoring bands, optimizes the smallest margin normalized by release variability, and fits seven outputs with normalized second-order terms. The robot loads chuck_shot_model.json once at program startup. Runtime work is polynomial evaluation and vector math; there is no trajectory search in targeting.

The baseline uses reference geometry and ideal transfer with unknown aerodynamic corrections disabled. It is not measured calibration. Gaps remain visible and invalid. Side trims, delay, rotation and tilt need repeated physical testing. Robot.java, ferry and feed controls are unchanged. No push or robot deployment has been performed.
